Implementation Plan: Client-Side Image & Vector Processing EngineProject Context: High-performance browser-based processing engine tailored for precision manufacturing (laser engraving, CNC routing, and digital fabrication workflows).1. Executive Summary & Architectural PhilosophyThe objective is to build a professional-grade image preparation and vectorization tool. The core architectural mandate is 100% Client-Side Computation. No image data is ever transmitted to a backend server. This ensures zero cloud compute costs, absolute user privacy, bypasses upload file size limits, and enables real-time visual feedback.Key Paradigms:Main Thread = UI Only: The browser's main thread handles DOM updates, state, and low-res previews.Web Workers = The Muscle: All heavy pixel manipulation and vector math occurs in background threads.WebAssembly (Wasm) = The Engine: Computationally expensive algorithms (CLAHE, dithering, contour tracing, distance transforms) are compiled to binary for near-native execution speed.2. Recommended Tech StackThis stack is designed for modern web standards, prioritizing Web Worker/Wasm integration without heavy configuration overhead.Frontend & BuildBundler: Vite. (Mandatory. Vite natively supports Web Workers and WebAssembly imports out of the box).UI Framework: React, Vue, or Svelte. (Engineer's choice, though React's ecosystem for complex canvas state management is highly robust).State Management: Zustand (React) or Pinia (Vue). Keep state lightweight; avoid Redux.Local Storage: localForage (IndexedDB wrapper) for storing large assets (custom material profiles, high-res cached states, ONNX models) without hitting localStorage's 5MB limit.Processing Core (The "Backend" in the Frontend)Language: Rust (compiled via wasm-pack) OR C++ (compiled via Emscripten).Recommendation: Rust is generally preferred for modern Wasm development due to better memory safety and excellent toolchains (wasm-bindgen).Worker Communication: Comlink. (A library by Google that abstracts postMessage into standard asynchronous function calls).Parallelization: WebGPU Compute Shaders (where supported) for massive pixel arrays, falling back to a Web Worker Pool based on navigator.hardwareConcurrency.AI Runtime: ONNX Runtime Web for executing machine learning models directly in the browser via WebGL/WebGPU.3. Comprehensive Feature MatrixA. Fundamental Image Manipulation (Canvas API / Wasm)These are standard adjustments that must apply in real-time on the preview canvas.Light & Tonal Controls: Brightness, Contrast, Gamma correction, Exposure, Levels (Input/Output mapping), and Tone Curve (S-curve mapping).Color Controls: Hue, Saturation, Lightness (HSL), Vibrance, Temperature, Tint, and Channel Mixer.Geometry & Layout: Crop (aspect ratio locking), Rotate, Flip, and Resize (DPI awareness for physical output).B. Advanced Enhancements & Filters (Wasm Required)CLAHE (Contrast Limited Adaptive Histogram Equalization): Essential for bringing out micro-details in flat areas without blowing out highlights.Adaptive Thresholding: Converts unevenly lit images to clean B&W based on local pixel neighborhoods.Clarity & Dehaze: Midtone contrast enhancement.Sharpening: Unsharp Masking and High-Pass filters to enhance edge contrast prior to dithering.C. Advanced Dithering Engine (Wasm / WebGPU Required)Standard Floyd-Steinberg and Bayer matrices are insufficient for premium output. The engine must include:Void-and-Cluster (Blue Noise Masking): A point-process algorithm utilizing a precomputed threshold matrix of "blue noise". It is perfectly parallelizable (ideal for WebGPU) and produces an organic, film-grain texture that avoids repeating grid patterns.Ostromoukhov's Variable-Coefficient: Dynamically adjusts error diffusion weights based on the input pixel's grayscale intensity. Completely eliminates "worming" or tearing artifacts in extreme highlights/shadows.Riemersma Dithering: Traverses the image along a space-filling Hilbert curve rather than scanning linearly. Prevents the directional horizontal/vertical banding that plagues linear error diffusion on CNCs.Knuth's Dot Diffusion: Divides the image into blocks and diffuses error based on a class matrix, breaking the strict sequential dependency of error diffusion.Standard Fallbacks: Error Diffusion (Floyd-Steinberg, Atkinson, Jarvis) and Ordered Dithering (Bayer crosshatch, Halftone dots).D. Advanced Vectorization Engine (Wasm Required)Converting raster bitmaps into production-ready, scalable vector paths (SVG/DXF) optimized for machine toolpaths.Multi-Color Vectorization (Trace by Color): Run K-Means clustering to reduce the image to a user-defined color palette, then generate isolated binary masks for each color. Trace each mask and group outputs into distinct SVG layers (<g>).Advanced Edge & Border Detection: Implement Canny and Sobel operators to extract continuous, single-pixel thin edges representing true physical boundaries.Centerline Tracing (Skeletonization): Utilize thinning algorithms (e.g., Zhang-Suen) to strip line thickness down to a single pixel before tracing. Ensure output generates as open SVG paths for single-line CNC scoring and v-carving.Node Optimization & Curve Fitting: Run the Ramer-Douglas-Peucker (RDP) algorithm to reduce node counts, followed by Bezier curve fitting (Schneider's algorithm) to translate rigid angles into smooth cubic Bezier (C/S) arcs.Boolean Cleanup: Integrate Clipper.js (or Wasm equivalent) to run union operations on overlapping paths, eliminating internal geometry that causes cross-cutting.E. 3D Depth Map Generation (ONNX / Wasm)Essential for 3D relief CNC carving and variable-depth laser engraving. Generates grayscale height maps where brightness equals Z-axis depth.Monocular Depth Estimation (AI): Utilize ONNX Runtime Web to run lightweight depth estimation models (e.g., MiDaS or Depth Anything V2) directly in the browser. Translates standard 2D photographs into pseudo-3D height maps.Vector-to-Relief (Distance Transform): Implement the Euclidean Distance Transform (EDT) on binary masks to algorithmically generate domed, prismatic, or beveled 3D height maps from flat 2D vectors/logos (simulates V-carving).Z-Axis Sculpting & Smoothing: Specialized UI controls where tonal adjustments map directly to physical height. Includes aggressive Gaussian smoothing algorithms to eliminate pixel-stepping.16-bit Export Pipeline (Crucial): 8-bit grayscale only allows 256 levels of height, resulting in physical "terracing" or stair-stepping on CNCs. The export engine must support generating true 16-bit PNG depth maps (65,536 levels of height) via raw ArrayBuffer compilation in the worker.F. AI Utilities & Workflow (Frontend State)Background Removal: U-2-Net/RMBG models executing locally via ONNX Runtime Web.Non-Destructive Architecture: Maintain an array of JSON objects representing edit steps. Build a Batch Processing pool to distribute JSON recipes across multiple Web Workers.Material Presets: Pre-configured JSON combinations of filters and dithering algorithms optimized for specific substrates (e.g., White Oak, Slate, Red Cedar).Live Previews & Inversion: Split-screen (Before/After). Include a UI-only color inversion toggle for visualizing burns on dark materials without affecting the output file.4. Implementation PhasesPhase 1: Scaffold & IPC (Inter-Process Communication)Set up Vite project.Establish the Web Worker architecture and implement Comlink.Phase 2: The Wasm Bridge & Basic AdjustmentsSet up the Rust (wasm-pack) compilation pipeline.Implement basic tonal adjustments to establish the rendering loop.Phase 3: The Preview vs. Export PipelineDual-Resolution System: Downscale loaded images for the UI preview. Only run the Wasm pipeline on the original, full-resolution image during Export.Phase 4: Advanced Algorithms, Vectorization, & Depth MapsPort the specialized dithering, CLAHE, and skeletonization algorithms into Wasm.Integrate ONNX Runtime Web and implement the 16-bit depth map export logic.Phase 5: State Serialization & Workflow AutomationImplement the JSON "recipe" tracking for non-destructive edits and build the Web Worker batch pool.5. Critical "Gotchas" & Best Practices (What to Avoid)AVOID Memory Leaks with Wasm: Explicitly free memory pointers when C++/Rust operations conclude, otherwise the browser tab will crash.AVOID postMessage Copying (Use Transferable Objects): Pass ArrayBuffer data directly as Transferable Objects between threads to achieve zero-copy overhead.AVOID Base64 for Large Images: Base64 strings use roughly 33% more memory than binary data. Keep image data as Blob, File, or ArrayBuffer objects.ONNX Model Loading: Machine learning models (MiDaS/RMBG) can be 20MB to 80MB. Do not bundle them in the main Vite payload. Lazy-load them from a CDN or public folder only when the user clicks the AI feature, and cache them in localForage for future sessions.OffscreenCanvas Fallback: Utilize OffscreenCanvas in the Worker for hardware-accelerated drawing, but ensure a software-level fallback for browsers with limited support.6. Testing StrategyPerformance Benchmarking: Write automated tests measuring the execution time of a 4K image running through a 5-step filter pipeline.Visual Regression: Create baseline image hashes and assert that the Wasm output precisely matches the expected byte array to catch compilation anomalies.
